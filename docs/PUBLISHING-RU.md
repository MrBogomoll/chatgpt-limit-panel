# ChatGPT Limit Panel 1.0: как подать в каталог плагинов ChatGPT

Проверено по официальной документации OpenAI 25 октября 2026 года. Готовая версия 1.0.0 для ручной установки и готовность к публичной модерации — разные состояния. Этот репозиторий остаётся приватным. Заявка в OpenAI не создавалась и не отправлялась.

## 1. Сначала получить допуск для локального MCP

ChatGPT Limit Panel запускает локальный MCP-сервер и программы Windows. Для такого типа плагинов OpenAI сейчас разрешает публичные заявки только одобренным партнёрам. Это обязательное условие текущего процесса, а не ошибка архива.

1. Открой настройки организации: https://platform.openai.com/settings/organization/general.
2. Найди Organization ID организации, от которой собираешься публиковать.
3. Свяжись со своим представителем OpenAI и попроси включить организацию в allowlist для local MCP / desktop-only plugin submissions.
4. Дождись подтверждения допуска. Если представителя нет, официальный документ не устанавливает общедоступный самостоятельный способ обойти это требование; сначала нужно выяснить возможность такого допуска у OpenAI.

Источник: https://developers.openai.com/plugins/deploy/desktop-only.

## 2. Подготовить сведения издателя

Нужны права владельца организации либо Apps Management Write, а также верификация физического лица или компании. Верифицированное имя издателя не равно произвольному имени GitHub. Текущее Local tools в исходниках нужно заменить подтверждённым именем перед публичной подачей.

Подготовь четыре реальные публичные HTTPS-страницы: сайт ChatGPT Limit Panel, поддержку, политику конфиденциальности, условия использования. Они должны открываться без входа, относиться к этому плагину и содержать соответствующую информацию. Ссылка на приватный GitHub этого не заменяет. Юридические обещания и имя издателя нельзя придумывать.

В манифесте это поля interface.websiteURL, supportURL, privacyPolicyURL, termsOfServiceURL. Для нового формата они лежат в extensions.com.openai.interface; в совместимом формате — в корневом interface. Иконка уже есть в assets/chatgpt-limit-panel.png, 512×512; версии manifest, MCP и UI согласованы на 1.0.0.

Источник требований: https://developers.openai.com/plugins/deploy/submission#listing-metadata.

## 3. Подготовить материалы проверки

Для первой проверки MCP нужны пять положительных и три отрицательных сценария, доступная проверяющим запись демонстрации и release notes. В docs/review-cases.md сохранены черновики сценариев; они не объявляются пройденными пользовательскими сценариями модерации. Технические тесты проекта не заменяют их выполнение.

Запиши на видео: установка на чистом Windows-профиле, карточка запуска, появление панели, три размера, полоски и контур, русский/английский, светлая/тёмная темы, остановка и повторный запуск. Покажи соответствие штатной панели квот, не раскрывая переписку и секреты. Сценарий записи не равен готовому видео: нужна настоящая запись и ссылка, доступная проверяющим.

Нужен заранее подготовленный способ тестирования локального Codex со входом и нужной подпиской. Не клади личные токены и пароль своего основного аккаунта в архив. Условия доступа проверяющих согласуются в защищённых полях портала и с представителем OpenAI для локального MCP. Также укажи страны доступности и сведения о наличии/отсутствии покупок; эти решения пока не заполнены от имени автора.

## 4. Загрузить черновик в портал

После получения допуска открой https://platform.openai.com/plugins, выбери нужную организацию/проект и верифицированного издателя.

Для локального MCP официальный специальный маршрут: **Create plugin → Skills only → Upload ZIP**. Несмотря на название Skills only, пакет должен сохранять реальную локальную MCP-конфигурацию. Не удаляй MCP, чтобы пройти форму, и не создавай фиктивный публичный HTTPS-сервер. Если названия кнопок изменились, ориентируйся на актуальную страницу desktop-only submission.

Для текущего настольного клиента собранный ZIP использует .codex-plugin/plugin.json. Авторский root plugin.json хранится в исходниках; не добавляй его в проверенный пакет без проверки поведения клиента/импорта порталом. При подготовке публичного ZIP внеси достоверные сведения издателя и остальные обязательные поля в выбранный формат, затем повторно собери и проверь архив. Текущий ZIP 1.0 для ручной установки ещё не содержит всех материалов публичной заявки.

## 5. Пройти проверки, отправить и затем опубликовать

Проверь импортированные поля в Metadata & Skills, устрани ошибки формата, заполни Review details и выполни применимые проверки. Юридические подтверждения должен дать уполномоченный издатель. Затем выбери Submit for review. Успешная загрузка ZIP сама по себе не отправляет заявку и не публикует плагин.

После одобрения отдельно нажми Publish plugin. Только после публикации плагин сможет появиться в общем каталоге. Это будет Desktop only; наша сборка поддерживает Windows x64 и локальные чаты. Доступность в браузере, на телефоне и macOS не заявляется.

Официальная инструкция: https://developers.openai.com/plugins/deploy/submission.

## Что можно сделать до допуска

Передавать готовый ZIP вручную. Другой пользователь устанавливает его в поддерживающем настольном клиенте, входит в свой локальный Codex и один раз нажимает Start/Запустить. Это не добавляет плагин в общий каталог. Для массового скачивания нужен отдельно доступный пользователям файл; приватный GitHub доступен только владельцу и приглашённым участникам. Репозиторий не переводился в публичный режим.

## Оставшиеся пункты публичной заявки

- Допуск организации для локального MCP и верификация издателя.
- Настоящее имя издателя вместо Local tools.
- Четыре проверенные публичные страницы.
- Демовидео и проверенный доступ для модерации.
- Прогон пяти положительных и трёх отрицательных пользовательских сценариев.
- Страны доступности, сведения о покупках, обязательные подтверждения портала.
- Проверка чистой установки на другом Windows-компьютере и реальной перезагрузки. Миграция нашей установленной беты проверяется отдельно; будущие смены пути задачи Windows ещё требуют контроля.
