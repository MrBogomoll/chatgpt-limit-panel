# Contributing

Read README and docs/BUILDING.md before changing the project. Use main for the current source and beta/ branches for experiments. Keep each change focused and include verification relevant to it.

- Preserve saved preferences, nonactivating input and the distinction between current, stale and unknown limits.
- Use fixtures and demonstration data for tests and images. Never commit credentials or personal desktop captures.
- Keep release versions consistent across the package, native product metadata, manifests, server and UI.
- Do not modify previously published archives or tags.
- Public release notes should describe changes for users.

For bugs, report Windows/client versions, display scale, view/theme and reproduction steps. Share cropped images with personal information removed.
